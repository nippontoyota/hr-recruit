# Site-wide frontend image assets

## Problem

The deployed recruitment portal renders broken images because frontend components use root-relative paths such as `/nippon-toyota-logo.png`. These paths depend on the deployment serving the Vite `public` directory at the same root as the SPA. The issue affects the shared brand mark and other direct image references across the frontend.

## Decision

Move the frontend image dependencies into the Vite-managed source graph and import them from a single asset module. Vite will copy and fingerprint these files during the build, and components will consume the generated URLs rather than assuming a static deployment root.

## Scope

- Add `frontend/src/assets.ts` (or equivalent focused asset module) importing the existing frontend image files.
- Update brand configuration and all direct frontend image references to use the imported asset URLs.
- Update the favicon to use the same source-managed asset path.
- Leave candidate-uploaded photos, resumes, blob URLs, backend PDF assets, and external image URLs unchanged; they are runtime/user content rather than bundled site assets.
- Do not change database schemas, records, API behavior, or storage data.

## Behavior and error handling

The rendered URL for each bundled asset will be generated by Vite and remain valid in production regardless of the hosting base path. Existing alt text, sizing, and brand selection behavior remain unchanged. Runtime image URLs returned by the API continue to be rendered as returned because they are not build-time assets.

## Verification

- Run the frontend production build and its existing dual-build verification.
- Inspect the generated `dist` output to confirm the bundled image files are present and referenced by the built HTML/JavaScript.
- Run the frontend lint command if the repository's current lint setup permits it.
- Confirm the diff is limited to the asset fix and does not include the user's pre-existing backend changes.
